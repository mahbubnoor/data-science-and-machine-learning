Call visualiser: frames appear, values go in, values come back

Every example from the lecture. Watch Python skip the function body at def, open a new frame at each call, and remove it at return.

What to notice

  • def only stores the function. Its body runs at the call.
  • Each call gets a fresh frame. Its names disappear when the call ends.
  • A function without return gives back None.
  • Untick "numbers and text inside the frame" to see that every name points to an object.

Argument matcher: which value goes into which parameter?

Pick a function, type a call, and see how Python matches arguments to parameters: by position, by keyword, or from a default. Wrong calls show the real error.

How the arguments are matched

What to notice

  • Positional arguments fill parameters left to right. Keywords fill by name, in any order.
  • Positional arguments must come before keyword arguments in a call.
  • A default is used only when nothing else filled that parameter.

Your results so far

What to notice

  • Methods like append and item assignment change the object, so every name for it sees the change.
  • lst = ... or n = n + 1 only moves the local name. The caller's name still points to the old object.
  • Numbers and text can never be changed in place. To send a new value out, return it.
  • Surprise: lst += [100] changes the list in place, but lst = lst + [100] does not.
