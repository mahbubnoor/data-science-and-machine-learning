Missing values: drop or fill?

  • dropna() removes rows with any missing value
  • Fast, but throws data away
  • fillna(median) keeps rows, guessing a typical value
  • Choose, and say which you chose in your report
Code
print(len(st), len(st.dropna()))
filled = st.copy()
for col in ["hours", "prior_gpa"]:
    filled[col] = filled[col].fillna(filled[col].median())
print(filled.isna().sum().sum())

StandardScaler: mean 0, standard deviation 1

Each column: subtract its mean, divide by its std · Every feature now has a similar range · Fit the scaler on training data only · Then transform both training and test data

Code
from sklearn.preprocessing import StandardScaler
num = filled[["hours", "attendance", "prior_gpa"]]
scaled = StandardScaler().fit_transform(num)
print(num.mean().round(1).to_dict())
print(scaled.mean(axis=0).round(2) + 0.0, scaled.std(axis=0).round(2))

Data leakage: the silent killer

1

What it is

Information from the test set sneaks into training, so scores look better than reality.

2

Common causes

Scaling or filling with statistics of ALL data; choosing settings on the test set; duplicate rows.

3

The fix

Split first. Fit every preparation step on training data only. Pipelines do this for you.

WATCH FOR

  • Wrong: the scaler learns from all rows, test included
  • Splitting afterwards is too late
  • Right: split first, lock the test set away
  • The pipeline fits on training rows only

A pipeline does every step, in the right order

Numbers: fill missing with the median, then scale · Categories: one-hot encode · Then the model · Inside cross-validation, each step is fitted on training folds only

Code
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import OneHotEncoder
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score
X = st[["hours", "attendance", "prior_gpa", "dept"]]
y = st["passed"]
prep = ColumnTransformer([
    ("num", make_pipeline(SimpleImputer(strategy="median"),
                          StandardScaler()),
     ["hours", "attendance", "prior_gpa"]),
    ("cat", OneHotEncoder(), ["dept"])])
model = make_pipeline(prep, KNeighborsClassifier())
print(round(cross_val_score(model, X, y, cv=5).mean(), 3))
Output
0.893

Does scaling really matter? Measure it.

  • Same pipeline, with and without the scaler
  • Same data, same cross-validation
  • k-NN gains a lot from scaling
  • A decision tree would barely change (try it)
Code
def build(scale):
    num_steps = [SimpleImputer(strategy="median")]
    if scale:
        num_steps.append(StandardScaler())
    prep = ColumnTransformer([
        ("num", make_pipeline(*num_steps),
         ["hours", "attendance", "prior_gpa"]),
        ("cat", OneHotEncoder(), ["dept"])])
    return make_pipeline(prep, KNeighborsClassifier())
for scale in [False, True]:
    s = cross_val_score(build(scale), X, y, cv=5).mean()
    print("scaled" if scale else "unscaled", round(s, 3))
Output
unscaled 0.687
scaled 0.893
